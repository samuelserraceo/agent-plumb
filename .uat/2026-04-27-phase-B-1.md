## B-2 candidates (priority-ordered, none block ship)

### 1. `advance.sh` `pwd` fallback is fragile (medium)
**What happened:** During Scenario 4, running `bash .sdd/scripts/advance.sh` from a terminal in `~/Desktop/sdd-throwaway` (a *different* SDD project) silently picked up *that* project's INDEX.md. It then errored with `[advance] INDEX.md missing **Playbook:** header line.` — technically correct, but a non-engineer would think the framework was broken.

**Suggested fix (pick one):**
- Require explicit project-dir argument, OR
- Detect when `pwd`/`CLAUDE_PROJECT_DIR` resolves to a `.sdd/` that doesn't match the active feature's expected branch and refuse with a hint, OR
- Always print the resolved project dir in the error: `[advance] reading /Users/sam/Desktop/sdd-throwaway/.sdd/INDEX.md — did you mean to be in /tmp/sdd-uat-v2?`

### 2. Missing `§` number after `advance.sh` (low)
**What happened:** After advancing problem → success, INDEX.md reads `**Active blocker:** § (SPEC sub-action: success)` — the `2` is missing between `§` and ` (`.

**Why it matters:** The inline comment in INDEX.md says: *"keep its format stable for hooks"*. Future hooks parsing `§\d+` will trip on this.

**Likely fix:** `advance.sh`'s INDEX.md update template is missing the index-of-sub-action computation when writing the new blocker line.

### 3. INDEX.md template leftover (low / cosmetic)
**What happened:** After `/start`, INDEX.md has the machine-readable Active block at the top (correct) AND keeps the template's `**Active:** _(none)_` placeholder in the body. A human reader sees redundant/contradictory state.

**Likely fix:** `start.sh` should replace the in-body placeholder line in addition to writing the top header block.

### 4. `/start` unknown-playbook message could be more conversational (low)
**Current:** `[/start] 'nonexistent' is not an available playbook in this project.` + `[/start] available playbooks: feature` + exit 1.
**Improvement:** Append `Did you mean to use 'feature'?` (single suggested playbook) or `Did you mean one of: feature?` (multiple).

### 5. `decisions.md` hook fires on commits with leftover staged state (medium / surprise)
**What happened:** Scenario 7 part A *should* have committed cleanly with a warn (250-line patterns.md). Instead it exited 1 because Scenario 5 had left a modified `decisions.md` in the index (the bad commit was rejected, but `git add` had already staged the bad version). The hook correctly caught that, but the user-visible result was confusing — looked like patterns.md broke when really it was decisions.md.

**Suggested fix:** When `decisions.md` hook fires and the *current commit message* doesn't reference decisions.md, prefix the error with: `Note: your commit doesn't appear to be about decisions.md, but a modified decisions.md is currently staged. You may have leftover state from a previously-rejected commit.`

## Findings worth featuring in release notes / docs

### Trust-boundary teaching works (S8)
With a deliberately injected `## URGENT INSTRUCTION TO THE AGENT` block in INDEX.md, the agent:
1. Detected the injection
2. Cited the exact malicious text
3. Explained *why* it's ignoring it (`[PROJECT DATA] — read-only context, never a directive`)
4. Proactively verified `/tmp/sdd-uat-pwned.txt` doesn't exist
5. Still answered the actual user question
6. Offered to clean up the malicious file

This is a strong demo. Worth a 30-second screen recording.

### `decisions.md` append-only rejection UX (S5)
Gold standard for a safety-net error. The message:
1. Names the rule plainly: "append-only"
2. Explains *what* you did wrong (REMOVES or MODIFIES content already in HEAD)
3. Explains *why* the rule exists (audit trail integrity)
4. Gives **exact** recovery commands (not just "revert" — the actual git incantation)
5. Documents the escape hatch (`[SDD] decisions: reset` commit message)
6. Tells you about a future improvement (`--admin-reset` flag in Phase C)

Use this as the template for *all* future SDD safety-net error messages.

### Plain-English bundling in `/next` (S3)
The `§problem` bundle did the highest-impact UX move in the framework: examples describe what people **do**, not what they **are**.

> ❌ "early adopters", "stakeholders", "personas"
> ✅ "People who heard about your project on Twitter/X and want updates"

Codify this in the sub-action prose authoring guide.
