Feature 006 — non-UI (safety hook)

Test-first mechanical check — verify RED before GREEN

A pre-commit hook that catches "fake test-first" — when the AI ships a test that passes without the code it's supposed to verify.

Flow — what happens when a BUILD task commit lands

Trigger

Agent runs git commit -m "[SDD:NNN][T01] task..." with a test file tests/task-001.<ext> and a code file staged together.

↓

Detect pair

Hook reads the staged set, looks for the tests/task-NNN shape paired with a non-test file in the same commit.

↓

Branch on test runner

Hook reads config.md → parameters.test_runner. If empty → Approach B (commit-order check). If set → Approach A (run the test).

↓

Approach B (no test runner)

Was the test file committed in a separate prior commit on this branch? If yes → allow. If no (test+code in same commit) → refuse with "test must land in its own commit first."

↓ OR

Approach A (test runner configured)

1. git stash push -- $code_files stashes only the code-side staged paths. Test file stays in index.

2. Run $test_runner. Capture exit code.

3. git stash pop to restore the code (always — even if step 2 errored, via trap).

↓

Test PASSED without code

Theatre detected → BLOCK.

The test doesn't actually pin behaviour — it was written to pass against whatever the code happens to do.

Test FAILED without code

Real test-first → ALLOW.

The test would have caught a missing implementation. Commit lands; spec.md row flips RED → GREEN as expected.

Architecture — where the new piece sits

Existing

.claude/settings.json — registers hook callbacks. templates/.claude/hooks/ — existing safety hooks (manifest pin, scope-guard, post-stop-lint).

New (this feature)

templates/.claude/hooks/pre-commit-test-first.sh — the hook. Wired in settings.json as a PreToolUse(Bash) handler on git commit.

Existing (read by the new hook)

.sdd/config.md — parameters.test_runner field. Empty by default, populated by /sdd-setup.

Existing (the framework's own test suite)

test/run-framework-test.sh — gets new T-tests covering each AC for this hook (T150-T158, one per AC1-AC9).

Concrete example — fake-test-first refused

Agent stages a test that passes without code (theatre). The hook catches it.

$ git add src/auth/login.ts tests/task-001.sh
$ git commit -m "[SDD:042][T01] login route GREEN"

[pre-commit-test-first] paired test+code detected:
  test:  tests/task-001.sh
  code:  src/auth/login.ts

[pre-commit-test-first] stashing code, running test (test_runner: bash tests/task-001.sh)...
[pre-commit-test-first] test PASSED without the code — theatre detected.

The test you staged passes WITHOUT the code it's supposed to verify.
That means it doesn't actually pin behaviour — it was written to
match whatever the code happens to do, not to fail before the code
existed. Future regressions will sneak past this test.

Fix:
  1. Rewrite the test against the not-yet-existing code shape.
  2. Run it — it should FAIL (because the code doesn't exist yet).
  3. Then write the code that makes it pass.
  4. Commit again.

Refusing the commit. (Stash restored.)
