🔘 All 14 slash commands

The main loop (you'll use these daily)

/start "<title>"

Scaffold a new feature, bug, or idea. Optional flags: --extends=<id> (evolution), --queued (backlog only).

/next

Advance the active work by one atomic step (= one commit). Your most-used button. Refuses on QUEUED state.

/status

Read-only "where am I?" — shows current feature, phase, blocker, and resolved settings.

/ship

Push branch, open PR, watch CI, mark shipped or auto-route failure back to BUILD as a bug.

/idea "<thought>"

Capture a half-formed thought to backlog. Single file, no ceremony. Convert with /start later.

/promote-to-active <id>

Flip a queued backlog item to actively-worked-on. Only needed if you used --queued.

Setup & config (occasional use)

/sdd-setup

First-session wizard — walks the 8 plain-English questions. Run once per project.

/sdd-config <id>

Re-answer ONE setup question without re-walking the wizard. Use when stack changes.

/settings <get|set|reset> <key>

View / change ONE parameter without editing YAML by hand. Faster than /sdd-config for one knob.

/sdd-verify-stack

Reality-check the tools you declared in /sdd-setup actually exist + are reachable.

/sdd-migrate [--apply]

Pull framework updates from upstream without touching YOUR specs / decisions / patterns.

/compress

Consolidate patterns.md or data-model.md when they grow noisy. Append-only safe.

Advanced (opt-in)

/ask "<question>"

Tier 3 LLM-powered Q&A over your project's own decision history. Requires MCP server + Tier 3 enabled.

/dispatch <role> "<task>"

Spawn a fresh-context sub-AI for one specific job. Roles: researcher (read), executor (write code), verifier (audit).

📝 The 8 setup wizard questions (deep-dive)
① What are you building?
Writes to: .sdd/stack.md · Change later: /sdd-config 001

Picks the project shape: website, phone app, backend service, internal tool (Railway), internal-tool-becoming-SaaS, CLI, scheduled script, or "something else" (describe). The choice cascades into default test runners, hosting, CI templates, and deploy commands. The "SaaS later" option flags every future spec to surface multi-tenancy concerns.

② Data needs?
Writes to: .sdd/stack.md · Change later: /sdd-config 002

None (static / calculator) · small spreadsheet-like data (SQLite) · accounts & content (Postgres via Neon/Supabase/Railway) · files / images / docs (blob store) · real-time data (chat / live cursors). Postgres triggers auto-seeding of .sdd/data-model.md with starter entity headings.

③ PR reviewer bot?
Writes to: .sdd/config.md under parameters.review · Change later: /sdd-config 003

CodeRabbit (recommended, free for OSS) · GitHub Copilot review · something else (Greptile, Qodo, custom) · no bot · decide later. CodeRabbit choice runs a walkthrough that opens the right pages in your browser + offers to seed .coderabbit.yaml. /ship polls the chosen bot's review state and auto-merges if clean.

④ Browser tests?
Writes to: .sdd/stack.md · Change later: /sdd-config 004

Full Playwright (desktop Chromium + iPhone-13 mobile viewports — catches layout breakage) · lightweight Vitest/pytest/Go-stdlib (faster, no UI bugs) · no UI to test · decide later. Also writes .github/workflows/sdd-ci.yml for CI on every PR + push.

⑤ Where will it run when shipped?
Writes to: .sdd/stack.md · Change later: /sdd-config 005

Laptop only · Vercel · Railway · Fly.io · Render · AWS / GCP / Azure (asks which sub-service) · Cloudflare Workers · private server (generates a Dockerfile) · decide later · something else. Shapes deploy commands + env vars for SHIP.

⑥ The 6 quick yes/nos
Writes to: .sdd/stack.md under ## Extras · Change later: /sdd-config 006

Six rapid Q&A. Sign-in? (Clerk / Auth0 / Supabase Auth). Email-sending? (Resend / Postmark / SendGrid / SES). Payments? (Stripe / Paddle / Lemon Squeezy). Error tracking? (Sentry / Honeybadger / Rollbar). Analytics? (Plausible / PostHog / Mixpanel / GA). AI in the product itself? (Anthropic / OpenAI / Gemini / Vercel AI Gateway / Ollama). Each "yes" updates data-model.md with the right schema additions.

⑦ Turn on the MCP server?
Writes to: .sdd/config.md under parameters.mcp · Change later: /sdd-config 007

Yes (saves 40–60% tokens once your project matures) · no (fine for <30 features) · tell me more. Runs install-mcp-server.sh if yes; if Tier 3 sub-questions follow, optional Ollama + Gemma chat-based answers over your project archive (local, no cost).

⑧ Automation level?
Writes to: .sdd/config.md under parameters.automation.level · Change later: /sdd-config 008 or /settings set automation.level <tier>

Full — auto-advance every technical step. Fastest, least oversight. Most (recommended) — auto-advance technical, prompt on destructive (mark-shipped, manifest-repin, branch-delete, decisions.md append). Checkpoint (default) — prompt on every AGENT-LED step. Slowest, safest. Sam-tip: start at Most; flip to Full once you trust the rhythm.

⚙️ Customisation — what you can tweak

Three ways to change settings. Pick whichever feels easiest — they all edit the same file (.sdd/config.md).

⚡
Fastest: /settings

Change ONE value at a time. Example: /settings set pace.halt_on_red_after_attempts 5. No YAML knowledge needed.

🪄
Guided: /sdd-config

Re-walks ONE wizard question with full plain-English context. Best when you're changing stack (new database, new reviewer, etc.).

📝
Power-user: hand-edit YAML

Open .sdd/config.md in any editor. Pure markdown + YAML — no special tooling. Save and the agent picks up changes next turn.

The most-tweaked knobs

parameters.automation.level — full / most / checkpoint (covered in Q⑧ above)
parameters.review.bot — coderabbit / sourcery / "" (no bot)
parameters.pace.halt_on_red_after_attempts — int, default 3. AI stops + asks after N failed test-fix attempts.
parameters.budget.max_minutes / max_tokens / max_commits — soft caps. AI warns at limit, never blocks.
parameters.test_runner — the shell command to run tests (e.g. npm test, pytest, go test ./...).
parameters.models.{thinking,routine,mechanical} — pick a specific Claude/GPT/Gemini model per cognitive tier. Empty = use the default.
parameters.injection.per_file_budget_chars — per-file size limits when the framework injects your project context. Sensible defaults already set.
parameters.review.bypass_cr_convergence — boolean. Lets /ship merge even when CodeRabbit hasn't approved yet. Default false. Flip with caution.
💡 When in doubt: type /settings with no arguments. It lists every knob with current values.

📖 The 5 memory files in .sdd/

These five plain-markdown files become your project's institutional memory. You can cat any of them in Terminal — no special tools needed.

📋 INDEX.md framework manages, you read

Work catalog — Active / In flight / Backlog / Shipped sections. The framework updates it as you /start, /next, /ship.

📜 decisions.md APPEND-ONLY (you can't edit past entries)

Timestamped audit log of every approval + phase advance. Hook refuses any commit that modifies prior entries. Reset path documented for emergencies.

🗂️ data-model.md you edit freely

Single source of truth for entities + fields across the whole project. Framework proposes additions during the data-contract action; you approve.

💎 patterns.md you edit freely

Cross-feature lessons — one block per pattern, source feature linked. Auto-appended by the learn action at SHIP time. Use /compress when it grows noisy.

🏗️ stack.md you edit freely

Your tech stack registry — database, hosting, auth, payments, etc. Filled by /sdd-setup and /sdd-config. Agent reads this every session to avoid contradicting it.

📐 principles.md you write

Project-wide invariants you want injected EVERY turn. Example: "all dates UTC", "no inline styles", "prefer copy edits over UI changes". The framework reads this before every /next.

📌 Plus one hidden file: .sdd/.cache/manifest.json — tamper-detection checksums. Never edit by hand. Framework manages it; commit hook refuses tampered framework files.

⚖️ Honest caveats — what Plumb gives up

Plumb is opinionated. It makes deliberate tradeoffs. Knowing them prevents disappointment.

⏱️ SPEC takes 30–90 minutes the first time.

If you want it built RIGHT NOW with no questions, Plumb is the wrong tool. It optimises for honest review over speed.

📵 No power-user shortcuts.

No terse aliases. No "skip the rubric for a quick exception." Every message is sized for a non-engineer reader. Engineers may find it verbose — that's the trade.

🚫 No silent assumption.

If your answer's ambiguous, the AI restates what it understood + asks. If preconditions aren't met, it halts. Slower; prevents "the AI quietly softened my approval."

📜 No deleting past decisions.

decisions.md is append-only. You can't rewrite history. If you need plausible deniability, this framework will frustrate you.

🔗 Must use git.

Atomic-step discipline runs on commits. Pre-commit hooks enforce. If you use git commit --no-verify often, you're bypassing the moat.

🏗️ Retrofitting onto existing projects is still rough.

Fresh repos work great. Projects with their own conventions (Husky / Drizzle migrations / existing PRDs) need an "absorb existing" mode that's still future work. File an issue if you hit this.

🧠 Not a silver bullet.

Plumb makes drift expensive and deep questioning cheap. It does NOT turn a bad idea into a good one. It does NOT replace product judgement. It IS a guardrail that catches the AI quietly cheating.

🆘 Troubleshooting + FAQ
"Claude says it can't find the marketplace"

Make sure you copied the WHOLE link including https://. Try copying again from this page. Also check you're on Claude Code (the app), not claude.ai (the chat website) — slash plugins are app-only.

"Nothing happens when I type /next"

Three checks: (1) Did you restart Claude Code after install? (2) Did you start a feature with /start? /next only works when there's something to advance. (3) Is the feature in QUEUED state? Run /promote-to-active first.

"How do I know it's actually working?"

First line of every Claude session should say [SDD bootstrap] ready. If you see that, you're good. If not — quit Claude fully (Cmd+Q on Mac, right-click tray icon → Quit on Windows) and reopen.

"A commit is being refused — what do I do?"

Don't bypass the hook. Read the error — it'll name the rule (theatre claim / append-only / approved-section changed / drift). The fix is usually: (a) revert the change, (b) re-approve with /re-approve <slug>, or (c) ask the agent to soften the wording. The hook is on your side — it caught a real problem.

"I want to try a real example before my real project"

Make a fresh empty folder. Open Claude Code in it. Type /sdd-setup, walk the 8 questions (pick simplest options), then /start "build a hello-world API endpoint". Walk it end-to-end with /next. Throwaway, but you learn the rhythm in 20 minutes.

"Windows: pre-commit hook fails saying 'bash not found'"

Plumb's hooks are bash scripts. Windows doesn't have bash by default. Install Git for Windows (includes Git Bash) — that adds bash to your PATH. Reopen Claude Code; hooks now work.

"How do I update Plumb when a new version ships?"

Two ways. Claude Code plugin path: /plugin marketplace update then /plugin install sdd@sdd-marketplace. Manual path: run /sdd-migrate (preview) then /sdd-migrate --apply. Your specs / decisions / patterns are never touched — only framework infrastructure.

"Can I run this without internet?"

Mostly yes. The framework itself is just bash + Python + markdown — runs offline. The AI calls (Claude, OpenAI, etc.) need internet. If you want fully-local AI, pick pi.dev path + use Ollama as your provider. Tier 3 chat-based search also works offline via Ollama + Gemma.

"What if I want to leave Plumb later?"

Delete the .sdd/ and .claude/ folders. Your repo keeps its git history + all the code you wrote. The framework was always just files you can cat — no servers, no SaaS, no lock-in. Your specs stay readable in any text editor forever.

"pi.dev: Can I really use my ChatGPT Plus or Claude Pro subscription without an API key?"

Yes — pi's /login command supports OAuth for Claude Pro/Max, ChatGPT Plus/Pro (via the Codex endpoint), and GitHub Copilot. No API billing. Honest caveat: Anthropic has been less stable about supporting heavy autonomous use of Pro/Max with third-party agents — could throttle or stop working without notice. ChatGPT Plus/Pro and Copilot are more reliable today. If predictability matters more than cost, use Path B (API key).

"pi.dev: My NVIDIA Build key works in the website demo but not in pi"

Three checks: (1) Did you install the extension? pi install git:github.com/xRyul/pi-nvidia-nim. (2) Is the env var exported in the SAME terminal you're running pi from? Run echo $NVIDIA_API_KEY to verify. (3) Both names work — NVIDIA_API_KEY or NVIDIA_NIM_API_KEY. If you set one and pi reads the other, you'll see "missing key." Set both to be safe.

"pi.dev: How do I switch between models mid-session?"

Inside pi, type /model (or press Ctrl+L). A picker opens with every model you've configured. Pick one — pi continues the conversation with the new model. Common pattern: use a big model (Claude Opus / Llama 3.3 70B) for thinking-heavy steps, switch to a small fast model (Groq, Cerebras, Gemini Flash) for mechanical steps.

"Which provider is cheapest for daily Plumb work?"

Three solid free options: NVIDIA Build (preview tier, rate-limited but generous — Llama 3.3 70B + DeepSeek R1 are excellent) · Ollama local (free forever, needs 16GB+ RAM) · Groq free tier (very fast, low rate limits). For paid: OpenRouter consolidates 100+ providers behind one key, so you can cost-shop per call. Anthropic + OpenAI direct API are pricier but the quality ceiling is highest.
