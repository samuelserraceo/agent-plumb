Per-file injection budgets in user-prompt-submit hook

Today the SDD hook concatenates all corpus files (INDEX, spec, principles, stack, data-model, patterns) into one big string, then truncates the END at 16K chars. On a mature project where patterns.md alone is ~20KB, the last file gets cut mid-paragraph or dropped entirely. This feature gives each corpus file its OWN char budget — when one file exceeds its budget, only that file gets truncated (with a sentinel marker pointing the agent at the Read tool to recover), and no file ever gets dropped wholesale from the injection.

Example interactions

3 examples — one per user story.

Story 1 — Sam (mature project, patterns.md ~20KB)

/next
The hook injects: INDEX.md (live-filtered, ~2KB), spec.md (~3KB), stack.md (3KB cap), data-model.md (3KB cap), patterns.md (4KB cap + sentinel).
patterns.md no longer gets cut mid-paragraph somewhere in the middle of the file — Sam sees the first 4000 chars consistently, with a sentinel telling the agent to Read the file if it needs the cut portion.

Story 2 — Lucia (downstream user, small patterns.md but huge data-model.md)

Edits her project's .sdd/config.md:
parameters: injection: per_file_budget_chars: patterns: 2000 # smaller; her patterns.md is small data-model: 8000 # bigger; she wants more of it visible
Next prompt: hook reads her override. patterns.md capped at 2000 chars (sentinel appended), data-model.md gets up to 8000 chars before truncation. INDEX/spec/principles/stack stay at framework defaults. Her per-project shape now matches her project shape.

Story 3 — AI agent (running the session)

[PROJECT DATA block injected by the hook]
Agent reads the injection and sees every corpus file represented — INDEX, spec, principles, stack, data-model, patterns. None dropped wholesale. When a file ends with the sentinel [truncated to <N> bytes per per-file budget — re-read with the Read tool ...], the agent knows there's more content available via the Read tool and proposes accordingly. No silently-cut content leading to contradictory suggestions.

What the injection looks like (concrete sample)

--- .sdd/INDEX.md ---
# SDD framework — INDEX
**Active:** features/011-...
[INDEX live-filtered: ## Shipped section removed]
(content here, capped at 3000 chars, no sentinel if under budget)

--- .sdd/features/011-.../spec.md ---
[active spec content, capped at 5000 chars]

--- .sdd/stack.md ---
[stack content, capped at 3000 chars]

--- .sdd/data-model.md ---
[data-model content, capped at 3000 chars]

--- .sdd/patterns.md ---
[first 4000 chars of patterns.md]
[truncated to 16012 bytes per per-file budget — re-read with the Read tool if you need the cut portion]
