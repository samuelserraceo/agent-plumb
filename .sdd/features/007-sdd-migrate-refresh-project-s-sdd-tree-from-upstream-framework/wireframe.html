Feature 007 — non-UI (CLI tool)

sdd-migrate — refresh Channel B from upstream framework

A CLI tool that makes the framework's project-template layer (.sdd/) updatable for downstream users without losing their project-specific data.

Flow — what happens when a user runs sdd-migrate

User runs (dry-run, default)

bash .sdd/scripts/sdd-migrate.sh --upstream=/path/to/sdd-framework

↓

Read manifest hashes

Tool reads user's .sdd/.cache/manifest.json (prior shipped hashes) and upstream's manifest. Walks every framework-tracked file path.

↓

Compute current user hash + upstream hash per file

Same normalised SHA-256 algorithm the framework uses (LF + strip trailing whitespace + strip blank-line edges). Categorise into 4 buckets.

↓

ADD

Upstream has the file, user doesn't. Safe to add (e.g., today's pre-commit-test-first.sh on a project from last week).

UPDATE-CLEAN

User's hash matches the prior shipped version, upstream has a newer one. User has stock content, just outdated. Safe overwrite.

UPDATE-CONFLICT

User's hash differs from BOTH upstream AND the prior shipped version. User has local edits — refuse to overwrite without confirmation.

REMOVED

Upstream removed the file but user has it. Listed for awareness; left alone (could be local addition).

↓ if --apply

Apply: per-file decision

ADD + UPDATE-CLEAN: applied automatically.

UPDATE-CONFLICT: prompts: keep / overwrite / show-diff. Default Enter = keep.

REMOVED: never deleted automatically. User decides via plain rm if they want.

↓

Re-pin manifest

Write the new .sdd/.cache/manifest.json with upstream hashes for all framework-tracked files (including ones the user kept). Manifest now matches reality; commits stop tripping drift errors.

Architecture — where the new piece sits

Existing

templates/.sdd/.cache/manifest.json — hash-pinned manifest of ~61 framework files. templates/.sdd/scripts/ — 18 framework scripts. templates/.claude/hooks/ — 9 hooks.

New (this feature)

templates/.sdd/scripts/sdd-migrate.sh — the migration tool.

templates/.claude/commands/sdd-migrate.md — slash command wrapper, calls the script with sensible defaults.

Excluded by hard-coded regex (user-data, never touched)

spec.md, INDEX.md, decisions.md, patterns.md, data-model.md, stack.md, principles.md, .sdd/features/**, .sdd/bugs/**, .sdd/refactors/**, .sdd/ideas/**, .sdd/.cache/manifest.json (managed separately at end of run).

Existing (the framework's own test suite)

test/run-framework-test.sh — gets T160 covering all 7 ACs end-to-end.

Concrete example — refresh a project that's missing today's test-first hook

User installed SDD a week ago; doesn't have pre-commit-test-first.sh. Runs sdd-migrate.

$ bash .sdd/scripts/sdd-migrate.sh --upstream=~/Projects/sdd-framework

[sdd-migrate] reading user manifest at .sdd/.cache/manifest.json …
[sdd-migrate] reading upstream manifest at ~/Projects/sdd-framework/templates/.sdd/.cache/manifest.json …
[sdd-migrate] hashing 61 framework-tracked files …

== Drift summary (dry-run) ==

ADD (upstream has, user doesn't):
  + .claude/hooks/pre-commit-test-first.sh
  + .claude/hooks/pre-commit-no-theatre.sh
  + .claude/commands/ask.md

UPDATE-CLEAN (user has stock prior version, upstream has newer):
  ~ .sdd/scripts/advance.sh
  ~ .claude/hooks/post-stop-lint.sh         (added invariant 10)
  ~ .claude/hooks/user-prompt-submit.sh     (added principles.md inject)

UPDATE-CONFLICT (user has local edits — confirmation needed):
  ! .sdd/actions/proposed-approach.md       (you edited this; upstream also changed)

REMOVED (upstream removed, user has — left alone):
  · (none)

To apply ADD + UPDATE-CLEAN automatically and prompt on UPDATE-CONFLICT:
  $ bash .sdd/scripts/sdd-migrate.sh --apply --upstream=~/Projects/sdd-framework
