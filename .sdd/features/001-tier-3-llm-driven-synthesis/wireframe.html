Visual walkthrough · non-UI feature · dogfood of issue #112

A knowledgeable colleague you can ask anything about your project.

Tier 3 lets you (or the agent) ask plain-English questions about your own SDD project — *"why did we pick Postgres?"*, *"what TODOs are piled up?"* — and get cited answers that always point at real pieces of your project. No hallucination. No invented links.

This page shows what that feels like, how the answer gets built, and where Tier 3 sits in the rest of the framework. Built for non-technical eyes — the load-bearing doc you read to confirm what we're building is what you actually want.

What Tier 3 actually feels like — five conversations

One example per user story from §3 of the spec. Read these like real chat transcripts. Click a citation in any answer to see what jumping there looks like.

Story 3 Decision recall — weeks later, you ask why
You · /ask "why did we pick Postgres for the waitlist?"
Postgres was picked because the v1 schema is small enough to colocate with the app — you flagged this in [[001-waitlist]] §5 about a month ago. Switching to a managed database came up later in [[005-pivot]] §3 but you parked it.

~1.5 sec to answer. Both citations resolve to real places in your project — click them and the editor jumps there.

Five TODOs across three in-flight features:
  • Cookie consent banner — [[009-onboarding]]

Story 1 Agent mid-spec — pattern lookup (data view)

Same Tier 3 brain, different wrapping. The agent (Claude Code) asks during a SPEC walk and gets back data it can act on directly:

Claude (mid-§5 proposed-approach) · synthesise(slug=current, question="is there a pattern for retry on transient failures?", format="structured")
{ "answer": "Yes — see [[pattern:auth-retry-logic]]", "cite_chunks": [{"slug": "pattern:auth-retry-logic", "path": "patterns.md", "line": 47}], "ambiguity": null, "ok": true }

Agent reads "yes — there's a pattern at line 47," decides to reuse it instead of inventing a new one. Saved roughly 20 KB of context that would otherwise have gone to re-reading specs.

Story 2 Agent at /ship — lessons synthesis

When the agent runs the `learn` action at `/ship` time, it asks Tier 3 what this feature should contribute to `patterns.md`:

Claude (running /ship learn action) · synthesise(slug=current, question="what should this feature contribute to patterns.md, given what already exists?", format="structured")
{ "answer": "Two new patterns. (1) cache-key-corpus-signature — distinct from [[pattern:hash-derived-cache]] because it composes existing v1.0 signature. (2) cite-check-rejection-fallback — extends [[pattern:fail-closed-with-explanation]].", "cite_chunks": [ {"slug": "pattern:hash-derived-cache"}, {"slug": "pattern:fail-closed-with-explanation"} ], "ambiguity": null, "ok": true }

Agent uses this as the basis for the actual patterns.md update — corpus-aware diff rather than a hand-typed guess.

Honesty floor What happens when the AI tries to invent a citation

If the AI makes up a link that doesn't exist — say it cites [[fake-pattern]] — Tier 3 catches it and shows you the raw chunks instead. You never see a confidently-wrong answer with an invented source.

You · /ask "is there a pattern for X?" — AI hallucinates a citation
Couldn't generate a clean answer — the AI cited a reference that doesn't exist in your project ([[fake-pattern]]). Showing the raw chunks the search found instead, so you can answer it yourself:
patterns.md §47 — auth-retry-logic: ...
patterns.md §62 — cache-warm-on-edit: ...
decisions.md 2026-04-22 — ...

No silent leak. No false confidence. The cite-check is mechanical — runs on every Tier 3 answer.

What's new in v1.1 vs what already exists

Tier 3 is mostly composition. The pieces that already work in v1.0 carry the load; the new pieces are tight and focused.

v1.0 — already shipped
  • · Wiki-graph — the [[link]] structure that Tier 3 navigates
  • · Graph cache — fast lookup + content fingerprint
  • · Search queries — neighbours, backlinks, scoped semantic search
  • · Corpus signature — drives cache invalidation

Tier 3 doesn't change any of these. Just reads them.

v1.1 — new in this feature
  • · synthesise() — the new MCP query (the brain)
  • · Synthesis cache — answers keyed by question + signature
  • · Cite-check — every [[link]] in an answer must resolve, or the answer is rejected
  • · Tier3Config — provider, caps, settings in config.md
  • · Wizard step — extension of brick 007 to walk Ollama+Gemma setup
  • · Ollama+Gemma — local AI on your machine (privacy by default)
v1.2+ — flagged for later, not in v1.1
  • · Other providers — OpenAI / Anthropic / etc. (settable manually in v1.1; wizard widening is v1.2+)
  • · Recursive / RLM-style — the AI decides what to fetch next, multi-round (current Tier 3 is single-round; recursion is a v1.2+ layer on top)
  • · Fuzzy cache matching — recognising rephrased questions as cache hits (exact-match only in v1.1)
