# Idea: Brief-builder pre-fills SPEC §0 instead of fully grilling from scratch

**Captured:** 2026-05-10
**Status:** captured

## What's the idea?
The brief generated by the `/write-brief` plugin (separate Claude session, 11-section format with lint gate) becomes the §0 input for SDD's feature playbook. SDD reads the brief, pre-fills §1, §3, §4, §6, §7, §8, §9, §10, §11 from the brief's corresponding sections, then grills only the gaps the brief didn't cover. SDD's grill becomes shallow audit-style ("does this contradict patterns.md / decisions.md / data-model.md? does this entity already exist?") instead of deep elicitation. Brief-builder grills the user's understanding (problem-aware, doesn't know the project); SDD grills the brief's fitness against the project corpus. Two pairs of eyes, different audit surfaces.

## What problem might it solve?
Today's SPEC requires deep grilling on every feature — roughly 20 questions to walk every section. Brief-builder already grills with its own lint gate before producing the brief. Running both in current shape = wasted time and same questions twice. Pre-fill drops SDD's grill to ~3-5 audit questions per feature.

## Why might it matter?
Probably the biggest single multiplier on SDD loop speed — 4-5x reduction in SPEC turns per the estimate in #207. Already partially scoped in v1.6 anchor as Part 1 ("§0 Brief intake replaces §1 problem"). Doctrine update: "trust the brief, audit don't redo."
