SDD feature 010 · framework BUILD-phase scheduler

Parallel wave execution

Independent BUILD tasks marked [WAVE: N] dispatch in parallel via Claude Code's Agent tool, each in a fresh per-subagent context. The orchestrator stays small (it gains ~1 turn per wave instead of ~30 linear). Cheaper models (Haiku, Kimi K2) run the wave-tasks in parallel while the orchestrator on Sonnet does coordination — the killer combo F008's multi-model unlock made possible.

Architecture (3 layers)

Flow 1 — Wave dispatch happy path

  1. /next reads spec.md → next-action.sh resolves { tag: WAVE-DISPATCH, wave: 1, tasks: [T200, T201, T202] }
  2. /next invokes dispatch-wave.sh 1 <spec-path>
  3. dispatch-wave.sh spawns 3 Agent calls in parallel (each gets fresh ~0-turn context + framework brain + single BUILD-task prompt + selected model)
  4. Each agent runs test → code → green as 3 atomic commits. Pre-commit hooks fire on each commit independently.
  5. dispatch-wave.sh awaits all 3 (synchronous, no polling)
  6. All 3 return success → /next reports "wave 1 done: T200/T201/T202 GREEN (9 commits)"
  7. Next /next picks up the next blocker (sequential T203, or wave 2)

Postcondition: 9 commits landed in non-deterministic order; spec.md has 3 newly-flipped GREEN markers; orchestrator's context grew by ~1 turn (just the dispatch + report-back), not 30.

Flow 2 — Wave-task fails mid-wave

  1. Same as Flow 1 steps 1-3
  2. T200 + T202 land 3 atomic commits each cleanly
  3. T201's Agent hits the anti-theatre hook (its test contained a guard-shaped sentence without {verify-by:} annotation). Pre-commit blocks; Agent reports commit failed.
  4. dispatch-wave.sh collects: 2/3 PASS, 1/3 FAIL
  5. /next reports honestly to Sam (see "Partial-wave report" example below)
  6. Sam picks retry T201, abandon wave 1 + advance, or pause to fix manually

Postcondition: spec.md has 2 GREEN + 1 still-RED for T201. The partial wave is honest about what landed. No silent half-state.

Flow 3 — Multi-model wave (the killer combo)

  1. Sam configures wave_worker_model: "haiku" in .sdd/config.md
  2. Same as Flow 1 steps 1-2
  3. dispatch-wave.sh reads the config — each Agent call passes model: "claude-haiku-4-x"
  4. 3 wave-tasks run on Haiku in parallel cheap workers while the orchestrator stays on Sonnet smart coordinator
  5. SDD discipline (anti-theatre, atomic-step, test-first, append-only) imposes the same shape regardless of model — discipline travels with the framework brain, not the model
  6. Wave finishes; cost/wall-clock numbers reported (best-effort: per-Agent cost field at SHIP)

Postcondition: same correctness as Flow 1, lower cost + faster wall-clock. The orchestrator earns its Sonnet rate on planning + coordination; mechanical BUILD steps run on Haiku where it's sufficient.

Concrete examples

Example A — Spec.md plan-decompose with wave markers

### action: plan-decompose - [x] tasks: 13 ordered T-tasks across 3 waves + 4 sequential ```text - [ ] T200 [WAVE: 1]: scaffold endpoint A (independent) - [ ] T201 [WAVE: 1]: scaffold endpoint B (independent) - [ ] T202 [WAVE: 1]: scaffold endpoint C (independent) - [ ] T203: integration test (depends on T200-T202 - sequential) - [ ] T204 [WAVE: 2]: docs sweep - [ ] T205 [WAVE: 2]: type-check sweep - [ ] T206: ship-check (depends on T204-T205 - sequential) ```

Example B — Partial-wave report (Flow 2 output)

$ /next Wave 1 finished partially: ✓ T200 (3 commits landed: test, code, green) ✓ T202 (3 commits landed: test, code, green) ✗ T201: pre-commit hook blocked the test step (anti-theatre claim on line 7 of tests/task-T201.sh - the guard-shaped sentence on line 7 needs a verify-by annotation) What next? retry T201 - re-dispatch just the failing task abandon wave 1 - flip the wave-1 marker off, T200/T202 stay GREEN, T201 stays RED, advance pause - stop here, fix manually, run /next again

Example C — Multi-model config (Flow 3 setup)

# .sdd/config.md (excerpt) parameters: wave: enabled: true worker_model: "claude-haiku-4-x" # workers run on Haiku # orchestrator inherits the session's selected model # (Sonnet by default in Claude Code) fallback_to_orchestrator_model: true # if worker_model # is unavailable on the harness, fall back silently
